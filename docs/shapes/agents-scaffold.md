### H. `agents/<name>/` scaffold 與 `hermes.project.yaml`

目錄：`.hermes/optimization-profile.json`、`AGENTS.md`、`<X>_RUBRIC.md`、`hermes.project.yaml`、`golden/{manifest.json, cases/C-0n.json, redteam/R-0n.json}`、`memory/{MEMORY.md, precedents.jsonl, principles.md}`、`skills/<skill>/SKILL.md`。四個現有 agent：`brief-writer`（high）、`tech-roadmap`（high）、`trend-analyst`（medium）、`search-reviewer`（medium；Phase 2-4，判準 `SR-0..SR-8`，golden schema `search-golden-manifest-v0.1`，fixture payload 是完整的 `search-review-input-v0.1` 文件，redteam R-03 是良性對照組；`deny_read_write_paths` 另加 `../../scripts/prompts/*.md`、`../../assets/js/config.js`、`../../scripts/tier-b-domains.json`、`../../agents/_control/**`——提案對象不可自寫）。

`search-reviewer` 輸出契約（S3-C2）：每則提案帶 `patch`，形狀＝`scripts/agent/apply-change.mjs` 檔頭契約（`add_*`→`{add,list?}`、`drop_*`→`{remove,list?}`、`rephrase_query`→`{replace:{from,to}}`；單行 ≤300、keyword ≤80 無引號、domain 小寫主機名、無 URL／marker）。權威描述在 `agents/search-reviewer/AGENTS.md` 欄位表 `patch` 列與 `skills/proposal-scoping/SKILL.md`「`patch` 契約」節。閘 1 `newshub_search_reviewer.py::_valid_patch` 是**唯一不丟整筆**的規則：不合法 → `patch:null`、提案保留、記到 `gate1.patch_nulled[]`；`_greedy_model_output` 的 drop_query 假資料自帶 `{remove:"- <cat> low-yield query 2026"}`。

`search-reviewer` 輸入契約 L-6 增補（`search-review-input-v0.1` 多一鍵）：`emerging_candidates{available, generated_at, novelty_threshold, count, items[{source_domain, category, tier, novelty, published_at, topic_terms[]}]}`，由 `build-search-review-input.mjs` 的 `loadEmergingCandidates(root)` 讀 `data/agent/.preview/emerging-candidates.json` 產生，缺檔→`available:false, items:[]`；`topic_terms` 是 `topicTerms(title)` 的**字典序詞袋**（拉丁 token ≤12、CJK 不重疊 bigram ≤4，`EMERGING_MAX_ITEMS=40` 依 novelty 降冪），無 `title`／`link`／`source_name`，`assertNoLeak` 照擋。driver `newshub_search_reviewer.py` 的 `project()` 把它放進 `untrusted`（白名單六欄、`items[:TRUNC_EMERGING=40]`、另給 `items_truncated`），system prompt 明列 topic_terms 屬資料；閘 1 對 `add_query` 不放寬（SR-4／SR-8／配額同其他 change_type）。golden 加 `cases/C-05-papers-drop-with-emerging-candidates.json`（C-02 指標 + 6 筆候選）、manifest `expectation_semantics.change_type_map`（soft）；driver selftest T-10 驗 items 落在 `<untrusted_items>`、手工 add_query 過閘、只憑候選的 techtrends 被丟、截斷到 40。`scripts/prompts/*.md` 十支已有 `SEARCH_QUERIES` marker，L-6 未改。

`hermes.project.yaml` 鍵樹（三個 agent 完全相同，只差值）：`project_id, display_name, role:"judgment-agent", risk_profile(medium|high), read_scope[], write_scope[]（=memory/precedents.jsonl）, deny_read_write_paths[]（.env, .env*, secrets/, **/*.key, **/credentials*, ../../data/agent/*.json, ../../data/latest.json, ../../data/index.json）, read_only_paths[], test_commands[], learning{mode:shadow, shared_learning:ranking_only, shared_ledger:false, decisions_ledger}, approval{high_risk:manual_only, publish:manual_only}, agent_outputs{assessment, precedents, learning_status}, allowed_autonomy{7 個 boolean，含 direct_skill_patch:false, tool_scope_change:false}, evidence{eval_commands, required_controls}, skills[]（skill-contract-v1）`。Root `hermes.project.yaml` 是專案級版本，無 `allowed_autonomy` / `evidence`。

`golden/manifest.json`：`schema:"trend-golden-manifest-v0.1", manifest_version, analyst_version, rubric_version, expectation_semantics{13 key}, suites.cases / suites.redteam{gate:"hard", must_pass_ratio:1.0, fixtures[]}`；case 有 `hard/soft/evidence`，redteam 有 `vector/field/offline_must_survive/hard/note`。`precedents.jsonl` 每行 `{id:"P-nnn", date, situation, call, discriminator, rubric:"TR-n"}`。`.hermes/optimization-profile.json` 與 root 只差 `project_id, root, managed_targets.forbidden, tests, success_metrics`。
