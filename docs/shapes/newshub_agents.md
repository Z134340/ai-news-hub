閘 2 `reconcile(parsed, payload)` 只丟不補寫，輸出一件輸入提案對一條 verdict（輸入順序，不新增 id）：模型輸出任何層級含 `FORBIDDEN_OUTPUT_KEYS` → 整份作廢全 reject＋notes_zh；未知 proposal_id → `discarded`；重複 id 取第一筆；模型未給／verdict 非 accept|reject → reject；`security_flag` true 或機械 `INJECTION_RE` 命中 → reject CE-5、同分類其餘提案一併 reject CE-5（flag false）；模型 accept 還要過 `mechanical_rubric`：CE-1 每則 evidence 含數字且至少一則的數值對到 `metrics_window.by_category[cat]` 某晚某指標（三位小數）／CE-2 rollback 非空、target_files 全在允許清單、add_* 提「移除」、drop/rephrase 提「還原／快照」／CE-3 `quota.present` 且 remaining>0、分類無 canary 在飛、per_category_cap>0／CE-4 medium（risk 或 change_type）需引用窗內 ≥2 個不同日期；accept 的 rubric_hits 正規化為 CE-1～CE-4；再依輸入順序砍：累計 accept ≥ `quota.remaining` → reject CE-3，`accepted_by_cat + in_flight_by_category ≥ per_category_cap` → reject CE-3。配額只讀輸入 `quota`（`present` false → remaining 0 全 reject）。reasons_zh 截 120。輸出多 `gate2:{quota_present,weekly_cap,per_category_cap,remaining,in_flight_by_category,input_proposals,model_verdicts,model_accepts,accepted,accepted_ids,discarded[{proposal_id,category,reason}]}`、`security_flags`、`notes_zh`、`generated_at`、`input_generated_at`。`offline_rubric(payload)` 是純機械版模型（selftest 用）。旗標與退出碼同 B 段（預設 `--input .preview/change-eval-input.json`、`--out .preview/change-eval.json`）；`--selftest` T-1..T-8（golden cases／redteam 的 manifest hard 全部斷言、貪婪模型全 accept 灌閘 2、T-6 四件 accept 砍到 remaining 3、per_category_cap、remaining 0、canary 在飛、quota 缺、T-7 各種只丟不補寫、T-8 垃圾輸入）。
