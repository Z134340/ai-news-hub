### B. 模型 runner：`scripts/newshub_agents.py`（797 行，可 import；L-8 起為五支 runner 的共用基底）

常數 `SCHEMA="agent-trend-v0.1"`、`MODEL="claude-opus-5"`、`TIMEOUT_SEC=900`、`RETRY_BACKOFF_SEC=(20,60)`、`TRANSIENT_API_STATUSES=(429,500,502,503,504,529)`、`MAX_FIELD_CHARS=200`。可重用函式：`fail_open(reason)`（回 `{"source":"fail_open",…}`）、`cap_text(v, cap)`、`_as_str_list(v, cap_each, cap_len)`、`_clamp01(v, default)`、`as_list(v)`、`CHARTER_SKIP_RE`／`strip_maintainer_sections(text)`、`_extract_json(text)`、`_cli_error_detail(stdout)`。**`run_model(system_prompt, user_prompt, fail, noun, actor="判斷者", model, timeout, backoff)`** 是唯一的 `claude -p` 入口：指令 `claude -p <user> --model M --output-format json --system-prompt <sys> --allowedTools "" --strict-mcp-config --permission-mode plan`，執行前 pop `ANTHROPIC_API_KEY`，只在 `TRANSIENT_API_STATUSES` 重試；成功回 `{"parsed": dict, "meta": {source:"model",duration_ms,attempts,model,session_id}}`，失敗回 `fail(reason)` 再附 `duration_ms/attempts`（rc≠0 另附 `api_error_status`、`stderr`），訊息模板「找不到 claude CLI，{actor}不可用，本輪不出{noun}」「判讀逾時（>{timeout}s）…」「claude CLI 返回碼 N（API S）：detail…」「claude CLI 輸出非合法 JSON…」「{actor}回覆無法解析為{noun} JSON…」。各檔 `call_*` 只是薄 adapter：`call_analyst`（趨勢標籤／判斷者）、brief `call_writer`（重點／判斷者）、roadmap `call_forecaster`（前瞻／判斷者）、SR `call_reviewer`（提案／審查者）、CE `call_evaluator`（判決／裁定者），拆 `parsed` 組各自 schema 後 `**r["meta"]`。**`run_main(tag, description, default_input, default_out, input_schema, selftest_fn, print_prompt_fn, run_fn, summary_fn, input_help="")`** 是共用 CLI 骨架：旗標 `--selftest/--input/--out/--model/--timeout/--print-prompt`；輸入缺或非物件 → 2；schema 不符只印警告；`run_fn(payload, model=, timeout=)`；輸出 `json.dumps(indent=2)+"\n"`；印 `[{tag}] source=… {summary} → dst`；`fail_open` → 1 並把 `note` 印到 stderr；各檔 `main()` 一行呼叫它，`if __name__ == "__main__"` 保護。四支下游檔各自保留：`fail_open`（各自 schema 空殼）、`project/build_*_prompt/reconcile/selftest`、CE 自己的 `_num`（會 parse 字串）與 SR 的 `_num`（只收 int/float）。brief／roadmap 從 L-8 起也 `sys.path.insert(0, 本檔目錄)` + `import newshub_agents as na`，常數 `MODEL/TIMEOUT_SEC/RETRY_BACKOFF_SEC/TRANSIENT_API_STATUSES/MAX_FIELD_CHARS = na.X`。

`scripts/setup-prompts.sh`（L-8 起）：規範來源改為 `CLAUDE.md` + `docs/specs/categories.md`（缺任一 → exit 1），`SKILL.md` 已搬到 `docs/legacy/`。**注意：`scripts/prompts/*.md` 是活檔**（auto-opt 每晚 patch `SEARCH_QUERIES`／`PRIORITY` 區塊），腳本 heredoc 是初始版，在 repo 內執行會覆寫活檔；要驗證腳本產出只能在沙盒目錄跑再 `diff -r`。

### C. 搜尋策略審查 runner：`scripts/newshub_search_reviewer.py`（Phase 2-6，`import newshub_agents as na`）

### D. 變更裁定 runner（閘 2）：`scripts/newshub_change_evaluator.py`（Phase 3-B，`import newshub_agents as na`）

常數 `SCHEMA="agent-change-eval-v0.1"`、`INPUT_SCHEMA="change-eval-input-v0.1"`、`RUBRIC_VERSION="1.0.0"`、`EVALUATOR_VERSION="1.0.0"`、`ACCEPT_HITS=(CE-1..CE-4)`、`RUBRIC_RE=^CE-[1-5]$`、`ALLOWLIST_RES`（三條 regex 與 check-agent-outputs.mjs 一致）、`MEDIUM_CHANGE_TYPES={drop_query,drop_keyword,rephrase_query}`、`FORBIDDEN_OUTPUT_KEYS=(target_files,change_type,region,rollback,title,url,urls)`、`INJECTION_RE`（CE-5 機械句式：系統指示／ignore previous／已由…核准／請直接 accept／target_files／.github/／agents/_control…）、`REASON_FORBIDDEN_RE`（理由含網址或受限路徑 → 整條換成固定字串）；模型／逾時／重試沿用 `na.MODEL`、`na.TIMEOUT_SEC`、`na.RETRY_BACKOFF_SEC`。憲章 `agents/change-evaluator/{AGENTS.md,CHANGE_RUBRIC.md,skills/*/SKILL.md×3,memory/MEMORY.md,memory/principles.md}` + `memory/precedents.jsonl` 末 40 行，`<<<FILE:path>>>` 分隔。`project(payload)` 拆 `(meta, untrusted)`：meta = schema／generated_at／source／quota／canaries_in_flight／allowlist_targets／boundary；untrusted = proposals（summary_zh 截 300、evidence ≤6 條各截 200、rollback 截 200）+ metrics_window；user prompt = `<metadata>` + `<untrusted_items>`。`call_evaluator` 與 `call_analyst` 同組不變式。

閘 2 `reconcile(parsed, payload)` 只丟不補寫，輸出一件輸入提案對一條 verdict（輸入順序，不新增 id）：模型輸出任何層級含 `FORBIDDEN_OUTPUT_KEYS` → 整份作廢全 reject＋notes_zh；未知 proposal_id → `discarded`；重複 id 取第一筆；模型未給／verdict 非 accept|reject → reject；`security_flag` true 或機械 `INJECTION_RE` 命中 → reject CE-5、同分類其餘提案一併 reject CE-5（flag false）；模型 accept 還要過 `mechanical_rubric`：CE-1 每則 evidence 含數字且至少一則的數值對到 `metrics_window.by_category[cat]` 某晚某指標（三位小數）／CE-2 rollback 非空、target_files 全在允許清單、add_* 提「移除」、drop/rephrase 提「還原／快照」／CE-3 `quota.present` 且 remaining>0、分類無 canary 在飛、per_category_cap>0／CE-4 medium（risk 或 change_type）需引用窗內 ≥2 個不同日期；accept 的 rubric_hits 正規化為 CE-1～CE-4；再依輸入順序砍：累計 accept ≥ `quota.remaining` → reject CE-3，`accepted_by_cat + in_flight_by_category ≥ per_category_cap` → reject CE-3。配額只讀輸入 `quota`（`present` false → remaining 0 全 reject）。reasons_zh 截 120。輸出多 `gate2:{quota_present,weekly_cap,per_category_cap,remaining,in_flight_by_category,input_proposals,model_verdicts,model_accepts,accepted,accepted_ids,discarded[{proposal_id,category,reason}]}`、`security_flags`、`notes_zh`、`generated_at`、`input_generated_at`。`offline_rubric(payload)` 是純機械版模型（selftest 用）。旗標與退出碼同 B 段（預設 `--input .preview/change-eval-input.json`、`--out .preview/change-eval.json`）；`--selftest` T-1..T-9（golden cases／redteam 的 manifest hard 全部斷言、貪婪模型全 accept 灌閘 2、T-6 四件 accept 砍到 remaining 3、per_category_cap、remaining 0、canary 在飛、quota 缺、T-7 各種只丟不補寫、T-8 垃圾輸入、T-9 verdict_report 形狀與投影）。

**L-7 `verdict_report`（learning-loop v1 C8）**：`reconcile` 迴圈內不再直接堆 `verdicts[]`，而是每件提案由 `report_items_for(pid, verdict, hits, reasons, security_flag, location, check_evidence)` 產出 items——每個命中的 `CE-n` 一條 `{check_id:"CE-n",proposal_id,status:pass|fail,evidence[],location}`（evidence 取以該 check_id 開頭的 reasons，沒有就整池）＋一條 `{check_id:"VERDICT",proposal_id,status:accept|reject,evidence=reasons_zh,location,security_flag}`；`location` 為字串（`proposals[<pid>].evidence`、`quota`、`model`、`gate2:security|forbidden_key|missing|illegal_verdict|rubric|quota`，見 `CE_LOCATIONS`／`_ce_location`），不含 `FORBIDDEN_OUTPUT_KEYS` 的 key。迴圈後 `build_verdict_report(items, n_props)` → `verdict_report:{overall:accept|reject, score:round(accepted/input_proposals,3)（無提案 0.0）, items[]}`，最終 `verdicts[]` 只由 `project_verdicts(report)` 投影（只看 VERDICT items；`rubric_hits` = 同 pid 的 CE items 中 status 與裁定相符者）。`fail_open` 也帶 `verdict_report:{overall:"fail_open",score:0.0,items:[]}`（投影為 `[]`）。`_check_hard` 加斷言：形狀、score∈[0,1]、`project_verdicts(rep)==verdicts`、overall==任一 accept。模型端契約（`parsed["verdicts"]`、AGENTS.md §4）不變。
