# SKILL — 把預測寫成能被打臉的形狀

適用於 `next_milestone` 與 `falsifier` 兩個欄位。上位規則:`ROADMAP_RUBRIC.md` RM-2。

## 為什麼要這麼麻煩

預測性判讀的失敗模式跟分類性判讀不一樣。分類判錯會被下一筆資料打臉;預測寫得模糊就**永遠不會被打臉**,於是永遠看起來是對的,於是三個月後沒人知道這條管線到底準不準。

`falsifier` 不是免責聲明,是對賭條件。一個好的 `falsifier` 會讓你在 horizon 結束時很難看——那正是它有用的證明。

## 三個組件

一句合格的 `next_milestone` 由三個組件構成,缺一不可:

| 組件 | 問題 | 反例 |
|---|---|---|
| **主體** | 誰/什麼會發生變化 | 「業界」「市場」——太大,無法觀察 |
| **可觀察事件** | 發生了什麼會被記錄下來 | 「越來越成熟」——沒有事件 |
| **量或界** | 多少、到什麼程度 | 「更多」——沒有基準線就沒有比較 |

`falsifier` 則是把三個組件否定後,加上**判定時點**(= `horizon` 上界)。

## 改寫範例

### 例 1:無主體

- 差:「多代理人協作會更普及」
- 問題:誰在普及?普及到什麼程度?怎麼看得出來?
- 好:「本叢集內出現至少 3 篇以具名企業為主體、描述多代理人系統上線的報導」
- falsifier:「3 個月後回看,具名企業上線報導仍為 0–2 篇」

### 例 2:有事件但無界

- 差:「開源實作會增加」
- 問題:增加多少算增加?從幾篇到幾篇?
- 好:「下一個 90 天窗內,本叢集的 E1 一手可復現來源比例超過目前的 20.8%」
- falsifier:「下一個窗的 E1 比例未超過 20.8%」

### 例 3:逃生門條款

- 差:「若無重大政策變化,本主題將在半年內進入產品化階段」
- 問題:「若無重大政策變化」讓這句永遠不會錯——只要沒發生就說政策變了
- 好:刪掉條件子句,或把政策變化本身寫成 `watch_signals` 的一條
- falsifier:「6 個月後仍無任何具名產品發布」

### 例 4:時間點與 horizon 不符

- `horizon` = `near`(0–3 個月),`falsifier` 寫「一年後仍未見…」
- 問題:對賭的判定時點跑到窗外,這一輪根本不會被檢驗
- 修法:判定時點一律寫成 `horizon` 的上界。`near` → 3 個月,`mid` → 12 個月,`far` → 明寫年數
- 沒改就依 RM-8 扣 0.2

## 自檢四問

寫完之後,對每一筆問自己:

1. **拿掉輸入還寫得出來嗎?** 寫得出來 → 這是背誦不是判讀,重寫或降 `unforecastable`。
2. **一個人在判定時點看一眼能判定嗎?** 需要另外做研究 → 太模糊。
3. **`falsifier` 成立時,`next_milestone` 一定不成立嗎?** 兩者可同時成立 → `falsifier` 沒咬住。
4. **加上「所以應該買進」還讀得通嗎?** 讀得通 → 已滑進 RM-0 投資建議禁區。

## 寫不出來的時候

寫不出合格的 `falsifier`,唯一正確做法是**該筆降 `unforecastable`、清空 `next_milestone`**。

**不要把里程碑改得更模糊來遷就。** 模糊的里程碑一樣會被寫進時間序列、一樣會被 dashboard 顯示,而它沒有任何資訊量。`unforecastable` 至少誠實。

## 與 watch_signals 的分工

- `next_milestone` 是**你賭它會發生**的那一件事(一件)。
- `watch_signals` 是**你不確定但值得盯**的事(0–3 件),不需要可證偽。

不確定的東西放 `watch_signals`,不要塞進 `next_milestone` 稀釋它。
