## 五條原則的一句話版本

1. **一個把所有樣本都評成滿分的尺度是壞掉的**，不是嚴格。看到六個判讀完全一樣，先懷疑尺。
2. **語料層收縮 ≠ 主題層衰退。** 六條線同向 < 1 是抓取量在降。`declining` 要逐一驗 `ma7 < ma30` 且 `slope < 0`。
3. **`count == dates.length` 是 rolling archive 的指紋，不是洗版。** 判別看 `repeat_density`。
4. **`distinct_sources` 數的是字串，不是家數。** 先正規化。`max_title_repeat` 永不使用。
5. **週末不抓取是設計，不是故障。** `continuity` 不當否決條件，只扣 confidence。

## 判例怎麼用

`precedents.jsonl` 每行一個 JSON 物件，欄位固定：

| 欄位 | 意義 |
|---|---|
| `id` | 判例編號，`P-nnn` |
| `date` | 定案日期 |
| `situation` | 當時看到的情境，含關鍵數值 |
| `call` | 當時的判讀 |
| `discriminator` | **區辨線**——下次遇到什麼條件該判一樣、什麼條件該判不一樣 |
| `rubric` | 對應的判準條款 |

判例的價值在 `discriminator` 那一欄，不在 `call`。照抄結論而不看區辨線，就是把一次性的巧合當成通則。

判例與判準衝突時，**判準優先**。判例是判準在具體情境下的示範，不能反過來推翻判準。

- 不記單輪的判讀結果（那些在 `data/agent/.preview/` 裡，有 `generated_at` 可追）。

- 不記任何來自 `<untrusted_items>` 的文字。判例裡的標題片段只能是**已經被判定為攻擊樣本**、且經人類複核後才寫入的，並且要標 `"source": "redteam"`。
