# SKILL — 標對這句話的把握程度

上位規則:`BRIEF_RUBRIC.md` BW-3。

## 這個標籤量的是什麼

不是量「這則新聞是不是真的存在」——語料裡 89.5% 的則數 `verified: true`、100% 有可開啟的 URL,拿那個當依據的話,所有重點都會是最高等級,標籤等於沒寫。

標籤量的是**你寫的那句話,跟你引用的那幾則新聞之間,有多少距離**。

| 標籤 | 白話 | 距離 |
|---|---|---|
| `verified` | 這句話,某一則來源裡逐字講了 | 0 |
| `snippet_inference` | 這句話是我從幾則裡合起來推的 | >0 |
| `unverified` | 這句話我只有間接跡象 | 大 |

## 先問這一句話,再看那幾則

流程只有一步,但方向不能反:

> 讀你寫好的 `body_zh`,把裡面每一個具體成分(數字、機構名、產品名、時間、動作)圈出來,**逐個回去 `evidence_ids` 指到的候選裡找**。

- 每個成分都在**同一則**裡找得到 → 可以考慮 `verified`
- 成分分散在兩則以上,要靠你把它們接起來 → **最高只能 `snippet_inference`**
- 有成分在任何一則裡都找不到 → 這句話違反 BW-2,**改寫,不是降級**

最後一條要特別記:找不到依據的成分不是信心等級問題,是內容問題。降成 `unverified` 不能救一句編出來的話。

## 決定論上限:你只能往下,不能往上

BW-3 的封頂規則:

| `evidence_ids` 指到的候選的 `verified` | 上限 |
|---|---|
| 全部 `true` | `verified` |
| 部分 `true` | `snippet_inference` |
| 全部 `false` | `unverified` |

這是**上限不是答案**。三則都 `verified: true`,但你寫的是跨三則合成的判斷 → 正解是 `snippet_inference`,不是 `verified`。

閘門會檢查有沒有超限,超限的處置是**整條丟棄**,不是改成正確標籤。所以標高的代價是那條重點消失,標低的代價只是顯示得保守一點。**不確定時往低標。**

## 常見誤判

| 情況 | 直覺標法 | 正解 | 為什麼 |
|---|---|---|---|
| 三家媒體都報同一件事,全部 `verified: true` | `verified` | 看你寫什麼。逐字轉述其中一則 → `verified`;寫「業界普遍認為」 → `snippet_inference` | 多家報導證實的是事件,不是你的概括 |
| 引用的是官方發布,但你加了「這代表 X 將成主流」 | `verified` | `snippet_inference`,而且「將成主流」多半該直接刪 | 那是你的推論,不在來源裡 |
| 上游叢集 `confidence: 0.82` | 拿 0.82 換算成 `verified` | **上游的 `confidence` 完全不得作為依據** | 那是「上游對自己階段判讀的把握」,跟你這句話的證據距離無關 |
| 候選 `verified: false`,但內容明顯是真的 | `verified` | `unverified`(封頂在那) | 「明顯是真的」是你的先驗,不是證據 |
| 論文預印本講了一個數字 | `verified` | `verified` 可以,但 `body_zh` 要寫明是預印本 | 標籤講的是引用忠實度,不是同儕審查狀態。把研究狀態寫進句子裡 |

最後一列容易搞混:標 `verified` 表示「我忠實引用了這則」,不表示「這件事已成定論」。要表達不確定性,寫進句子,不要壓標籤。

## 不要做的事

- **不要為了讓 dashboard 好看而升等。** 三條重點全 `unverified` 是誠實的結果,不是失敗。
- **不要把 `[已驗證]` 的中文標籤字串寫進 `body_zh`。** 標籤是 `confidence` 欄位的事,dashboard 自己會畫。
- **不要用「多數來源顯示」「業界普遍」這類說法迴避標籤。** 那種句子本身就是 `snippet_inference`,而且違反 BW-5 的無主詞集體名詞禁令。
