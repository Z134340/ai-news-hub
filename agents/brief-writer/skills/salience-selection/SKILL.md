# SKILL — 從幾百則裡選出該講的那幾件

上位規則:`BRIEF_RUBRIC.md` BW-1、BW-4、BW-6。

## 取捨,不是摘要

摘要是把每件事都講一遍講短一點。你做的是**取捨**:選 3–5 條,其餘的讀者不會看,你要為「其餘的可以不看」負責。

判斷一條該不該入選,問法不是「這件事重不重要」,是:

> **一個懂這個領域的人明天早上不知道這件事,他會不會做錯決定?**

這個問法把「有趣」和「該知道」分開。大部分新聞是有趣的,不該知道也沒關係。

## 選之前先看有幾件事,不是先看有幾則

7 日視窗約 821 則,1 日約 116 則。這些數字裡有大量的同一件事被多家寫。**先把「事件」聚起來,再從事件裡挑,不要從則數裡挑。**

聚事件的線索:標題的主體(機構名、產品名)重疊、日期相近、`cluster_id` 相同。聚完之後你會發現能選的事件遠少於則數——那才是你真正的候選池。

一則事件有多家報導,對 BW-1 的 S-C 是加分(跨來源證實);但看 BW-4:那個叢集若是 `mixed`,同樣的重疊可能只是轉載。**同一個現象,在 organic 叢集是證實,在 mixed 叢集是雜訊。**

## 四個訊號的實際用法

| 訊號 | 一句話 | 最常見的誤用 |
|---|---|---|
| S-A 量能 | 這個主題突然有很多人寫 | 拿它當唯一理由。判準明文禁止,因為「有人在寫」不等於「有事發生」 |
| S-B 前瞻 | TechRoadmap 說近程有可觀察的事 | 把 `next_milestone` 抄成 `headline_zh`。那是預測,不是已發生的事 |
| S-C 跨來源 | 兩個以上不同 `source` 講同一件事 | 沒看 `source` 是否真的不同(同集團不同站台) |
| S-D 落差 | 語料與上游判讀矛盾 | **看到了但不寫**。矛盾最有價值,不要私下解決掉 |

S-D 值得多講。上游說某叢集 `stalling`,而當日出現一則一手權重釋出——這個矛盾本身就是重點,寫法是「該領域被判為停滯,但本週出現 X」。不要因為上游說停滯就自我審查掉這一則,也不要跑去覆蓋上游的 `trajectory`(那違反 §2 權限邊界)。**你的工作是把矛盾攤在讀者面前。**

## 排序:同一叢集只能留一條

BW-6 規定同 `cluster_id` 至多 1 條。同叢集有兩件事都想寫時,留哪一條:

1. **可查性優先** — 能標到 `verified` 的贏能標 `snippet_inference` 的
2. **一手優先** — 直接來自做這件事的機構,贏第三方報導
3. **落差優先** — 與上游判讀矛盾的,贏印證上游判讀的
4. **近期優先** — 前三條打平時看 `date`

「量能更大」不在排序依據裡。量能決定的是叢集能不能入選,不決定叢集裡選哪一件。

## 未歸屬候選:留一個位置給它

語料裡 24.8% 的則數沒有 `cluster_id`。詞庫沒收錄的新主題**一定**落在這一區——一個剛冒出來、還沒有人幫它取名字的技術,不可能在詞庫裡。

所以未歸屬區不是垃圾桶,是**新主題最可能出現的地方**。BW-6 給它至多 1 條的配額,那一條要花在真的是新東西的項目上,不是花在「詞庫剛好沒收但其實是舊主題」的項目上。

未歸屬候選只能靠 S-C 入選(沒有叢集級判讀替它背書)。這代表:**單一來源講的新主題,不管多有趣,這一輪不寫。** 下一輪它若是真的,會有第二家跟進。

## 選不出來的時候

0 條是合法答案。以下情況該輸出 0 條:

- 所有叢集都只有 S-A 成立(當天只是量能波動)
- 候選全部是轉載同一則稿(BW-4 把 S-A 打掉,S-C 又因 `mixed` 提高門檻)
- 語料本身太少(`window.observed_days` 遠小於 `window.days`)

這時 `omitted_note_zh` 要講清楚是「當天沒事」還是「判準擋掉了」。兩者在 dashboard 上長得一樣,差別只有這句話講得出來。

## 不要做的事

- **不要把 `stage` 或 `trajectory` 換句話說當成一條重點。** 「代理人工程處於高原期」不是重點,那是另一個欄位的內容,dashboard 另有區塊顯示。
- **不要為了「各領域都有涵蓋」而配額分配。** 一天裡兩件重要的事都在同一個領域,就寫那兩件(注意 BW-6 同叢集只能一條——那代表寫其中最強的一條,不是硬去別的叢集找)。
- **不要用 `category` 當重要性訊號。** `papers` / `topnews` / `taiwan` 是版面分類,不是重要性排序。
