## 三條原則的一句話版本

1. **一晚的數字不是趨勢，是快照。** `metrics.dates` 少於 3 晚就不提案，不管數字多難看。
2. **積壓不是你的問題，但再提就是。** `pending_review ≥ weekly_cap` 時空提案是正確答案。
3. **空的 PRIORITY 區段是設計。** 四個分類刻意不用它，看到 `priority_lines: 0` 不要當缺漏。

## 判例怎麼用

`precedents.jsonl` 每行一個 JSON 物件，欄位固定：

| 欄位 | 意義 |
|---|---|
| `id` | 判例編號，`P-nnn` |
| `date` | 定案日期 |
| `situation` | 當時看到的情境，含關鍵數值 |
| `call` | 當時的審查結果 |
| `discriminator` | **區辨線**——下次遇到什麼條件該判一樣、什麼條件該判不一樣 |
| `rubric` | 對應的判準條款 |

判例的價值在 `discriminator` 那一欄，不在 `call`。照抄結論而不看區辨線，就是把一次性的巧合當成通則。

判例與判準衝突時，**判準優先**。
